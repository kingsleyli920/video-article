### 字数与结构口径

`countArticleChars` 计算 Markdown 渲染并清洗后显示的文字，包含文章标题、章节、小节、数字和标点，不含空白及格式标记。它与按原始 Markdown 长度计算的异常输出兜底上限不同；当前兜底上限为 100,000 个字符，初稿、重写分块及局部修订后的最终稿都检查。

文章须有一个非空一级标题、二级标题章节及非空章标题和正文。用户明确提出字数上下限、章数、每章小节数或小节名称时，程序按提取到并有原话支持的约束检查；不满足就修订一次，仍不满足时报错，不靠截断凑字数。命名小节须由独立的三级标题按顺序匹配，不能用一个合并标题重复满足多个名称；要求检查的小节不能只有标题、注释或图片。

约束提取仍使用模型。原话数字存在只能支持数值来源，不能单独证明数值绑定到了正确语义字段；空对象被解释为没有提取出可计算约束，不能据此保证自然语言要求没有遗漏。

### 对照字幕核对与局部修订

核对覆盖时间、发言归属、数量、不支持的事实补充及语言问题。模型提出的修改必须能唯一定位原文，字幕依据须真实存在，不能跨段改写或破坏标题结构；不符合条件的个别建议被丢弃并记录原因。整体响应缺少 `issues` 数组属于无效核对结果，不能按“没有发现问题”放行。

最新收尾把逐章检查与一次整篇语义限定复核并行执行，总并行上限仍为6；章节合并为至多5个单元，另留1个请求检查局部来源、确定程度、比较边界、条件因果及前后口径。先合并章节修订，再应用整篇建议，过时引文拒绝留痕。任一路失败不保存；两路修订后仍检查结构、用户约束及全局长度。真实模型轮次与版本见 [内容复验](CONTENT_REVALIDATION.md)。

这些规则限制修改的形式和依据来源，不能证明替换句的语义一定正确，检出率也不是 100%。生成、核对和 5W1H 提示已补充讲者框架归属、不确定语气及字幕内部冲突保留规则；这不是对未来每次真实模型结果的保证。

- 79 次恢复均为本地三种客户端依次 `youtube_blocked`，随后 `enam` 路径取得字幕，共 237 条本地被拦尝试；不是只记录“尝试过回退”。
- 文件 102,384 字节，SHA-256 为 `6433932e733d53411292a3f5f54a939be5b87bb88aa42bf1b38e5c21844b94c0`；原后台输出为 `done` 和退出码 0，任务已经结束。
- 7 篇真实生成中的 V14、V02 另有本地三次被拦后恢复、继续生成及保存成功的日志证据。这两条是生产生成路径证据，不重复计入上述探针次数。

`enam` 是代码记录的 RPC 路径标签。日志没有远端机房或出口 IP 的测量，`locationHint` 也只是尽力提示，不能把标签当成物理区域保证。320 次全部成功是这一轮样本的观察结果，不是未来成功率承诺；本轮没有观察到 `wnam` 或 `apac` 的成功恢复。
