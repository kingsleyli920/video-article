# 模型配置评估与历轮线上验收记录

这份记录是从 README 移过来的过程材料：第八轮的模型对照和推荐、切换到 `gemini-4-hydrogen` + high 之后的第一次线上验收，以及当时的验证摘要。
它们写于"文章写完后再对照字幕核对"这个阶段加入之前，其中列出的内容偏差（年份错绑、引用归属、数字范围等）后来成为核对与局部修订的目标，不能据此认为已经全部消除；现状以 README 和 [需求验收对照](REQUIREMENTS_ACCEPTANCE.md) 为准。

## 一、第八轮：模型配置评估与推荐

**推荐**：主模型 `gemini-4-hydrogen`，思考档 `high`；备用模型仍是 `gemini-3.6-flash`；首个分块时限 180 秒，其余时限不变。这套配置已经采用并上线，上线后的配置和验收见[本文件第二节](#first-online-acceptance)。本节保留评估时的数据和理由，当时线上还是 `gemini-3.8-flash` + `low`。

完整数据、逐篇偏差和原文核对见 [测试矩阵第 11 节](TEST_MATRIX.md)。

### 各候选的内容、等待时间和费用

所有候选都用同一份遮蔽后的字幕、同一份元数据和生产提示词，不切换备用模型。时间是到达脚本的时间，从发请求算起。

| 配置 | 首个可读段落 | 全文 | 每篇费用 | 内容偏差 |
|---|---|---|---|---|
| `gemini-4-hydrogen` + high（2 篇） | 52 秒、80 秒 | 103 秒、135 秒 | 0.17、0.20 美元 | 第 1 篇有 4 处小偏差（AD 展开成"美国活力"、50 亿和 50 到 60 亿混写、1994 年和谷歌混写、tripling 写成"加倍"）；第 2 篇检查点全对 |
| `gemini-4-neon` + high（2 篇） | 113 秒、144 秒 | 233 秒、244 秒 | 0.40 美元 | 细节最全，都能找到原话；第 1 篇全部提问署名 Jen Kha（有依据，但不能证明每问都是她）；"加倍" |
| `gemini-4-carbon` + high（1 篇，另有 1 次失败） | 582 秒 | 667 秒 | 0.48 美元 | 细节都能找到原话；同一位提问人混用两种署名；"加倍"；50 亿混写 |
| `gemini-4-hydrogen` + low（第七轮，2 篇） | 首个文本 11、29 秒 | 44、47 秒 | 0.09、0.10 美元 | 篇幅只有 high 的一半到四分之三；两篇都把 AD 展开 |
| `gemini-3.8-flash` + low（线上，第七轮 2 篇、本轮线上 1 篇） | 首个文本 2 到 3 秒；线上首个可读段落 4.2 秒 | 41 到 82 秒 | 约 0.035 美元 | 字幕外扩写（"结合垂直领域数据""国防"）；本轮线上那篇压缩成 4 章，"算盘"、"网景"、占位嵌进句子 |

五篇高档输出在四个检查点上都做对了：数量级写"数千亿甚至数万亿"，法案数量保留"数字不清"，应用公司自研模型的依据写"对垂直领域的理解"、不加"数据优势"，52:00 的投资关系写成"我们投资了 Ilya、Mira Murati、李飞飞"。高档之间的差别主要在等待时间和费用上，内容上 Neon 和 Carbon 细节更多，但没有明显更忠实。

**付费层**：Carbon 和 Neon 只有付费层，Hydrogen 有免费层也有付费层。本轮全部在付费层上测（预付费，未开自动续充）。第三轮免费层时 Hydrogen 出现过首个正文 51 秒和流中途 503，免费层下的表现没有在本轮复测。

### 缓存和实际服务档

- **服务档**：所有响应的 `usageMetadata.serviceTier` 都是 `standard`，响应头 `x-gemini-service-tier` 都没有返回。
- **Priority**：没有测。按账单规则推断，这个项目只能是 Tier 1（今天首次付费，预付 5 美元；Tier 2 要求累计付费 100 美元且满 3 天），不满足 Priority 的条件。没有只读接口可查层级，没有改账单设置。
- **缓存**：提示词本来就是"系统规则 → 视频信息 → 字幕 → 用户要求"，稳定的部分在前。本轮所有响应都没有报告 `cachedContentTokenCount`，同一份请求连发两次也没有；第七轮曾看到约 2.5 万 token 命中。命中与否不由我们控制，不算作本轮的优化。

### 本轮做了哪些改动，哪些起了作用

| 改动 | 作用 |
|---|---|
| `maxOutputTokens` 文章 32,768 → 65,536，5W1H 4,096 → 65,536 | 高档思考的前提。5W1H 在 high 下思考 3,000 到 5,000 token，旧上限会截断；Carbon 一篇思考加输出 4.2 万 token |
| 首个分块时限 120 → 180 秒 | Hydrogen high 首个正文 51 到 83 秒，120 秒余量不够；不改的话候选配置偶尔会被误判为繁忙、改用备用模型 |
| 记录首个可读段落、用量（含思考 token）、实际模型版本、服务档 | 本轮所有对照和验收的数据来源；也是确认"没有静默换模型"的依据 |
| 来源面板和字幕原文片段 | 等待体验。高档思考下正文要等 1 分钟以上，面板在 0.8 秒出现，读者先看到依据的是哪个视频、哪份字幕、是否用了备份 |
| 字幕片段在短字幕时不重叠 | 小修正 |

没有改提示词，没有做缓存重构，也没有做简介分区：本轮输出里 Erik Torenberg 只出现在"a16z 对外传播团队"的语境里，没有被当成本期主持人，没有观察到简介污染。

### 推荐的模型、思考档和等待配置

| 项 | 值 | 依据 |
|---|---|---|
| 主模型 / 思考档 | `gemini-4-hydrogen` / `high` | 内容和 Neon、Carbon 同一水平；首个可读段落约为 Neon 的一半、Carbon 的九分之一，费用约为 Neon 的一半；比 Hydrogen low 覆盖面宽、字幕外补充少 |
| 备用模型 | `gemini-3.6-flash`（不变） | 只在主模型开始输出前持续繁忙时启用；`done` 和状态条会注明 |
| 首个分块 / 输出空闲 | 180 秒 / 60 秒 | 实测首个正文最慢 83 秒；开始出字后分块间隔在 1 秒以内 |
| 5W1H 主模型 / 主备合计 / 前端 | 50 秒 / 85 秒 / 100 秒（不变） | 本地验收 19.5、21.8 秒，直接调用 32.5、36.3 秒 |
| 前端空闲 / 总时限 | 45 秒 / 10 分钟（不变） | Worker 每 15 秒发心跳；Hydrogen high 全文 103 到 136 秒 |

**代价**：读者要等约 1 分钟到 1 分半才看到第一段正文，比现在的 3.8 Flash（4 秒左右）慢得多；每篇约 0.15 到 0.20 美元，每章 5W1H 约 0.07 美元，大约是 3.8 Flash 的 5 倍。等待期间有阶段、已用时间、来源面板和"停止生成"，没有假进度和假打字。是否接受这个等待是产品取舍，所以第八轮没有改线上配置；看完这一轮的结果后决定接受，线上已经切换，见[本文件第二节](#first-online-acceptance)。

### 是否需要新的生成阶段

不需要。剩下的偏差都是小处，比如提问人署名前后不一致、tripling 写成"加倍"、50 亿和 50 到 60 亿混写。和线上 3.8 Flash 相比，Hydrogen high 的字幕外扩写少了，主要事实没有错。

如果以后要加，最小的做法是保存之前做一次"证据核对加局部修订"：

- **做法**：拿全文和字幕，让模型列出有疑点的句子，并给出字幕原文位置和修订后的句子；程序只替换这几句，不重写全文。
- **预期收益**：预计能修掉上面这类小偏差，对已经正确的主要事实没有帮助。没有实测。
- **增加的等待**：高档思考下估计 30 到 60 秒，参照 5W1H 的实测。
- **一致性**：正文已经流式展示给读者，修订不能悄悄替换。修订后的句子要在页面上标明"已按字幕修订"，并能看到原句；`done` 和 Durable Object 只保存修订后的版本；章节 id 由章节解析生成，只改句子不改标题，id 不变；5W1H 只在保存之后才能生成，所以不会缓存到修订前的版本。
